# 從安裝到印出第一張單

> 目標：**十分鐘**。看到第一張單從印表機吐出來為止。
>
> 這一頁是給要開店的人看的，不是給工程師看的。看不懂的地方請開 issue ——
> 說明書看不懂是說明書的問題。

---

## 開始之前

| 你需要 | 說明 |
| --- | --- |
| 一台 Windows 電腦 | 迷你主機就夠。**它同時是伺服器，營業時間請不要關機** |
| 一台網路型出單機 | 支援 ESC/POS、走網路線（TCP 9100）。USB 與藍牙還不支援 |
| 一條網路線 | 出單機接到跟電腦同一台路由器 |
| （強烈建議）一台 UPS | 一千元的不斷電系統，比這個專案裡任何一行程式碼都更能提升可用性 |
| （建議）一支 USB 隨身碟 | 常插著，當第二份備份的位置 |

**還沒有出單機也可以先玩。** 下面每一步除了「接印表機」以外都能照做，
單子會排在佇列裡等機器接上來。

---

## 1. 安裝（1 分鐘）

到 [Releases](https://github.com/markku636/open-pos/releases) 下載
`open-pos_x.y.z_x64-setup.exe`，雙擊安裝。

> Windows 可能會跳「不明的發行者」。這個專案沒有買程式碼簽章憑證
> （一年要價數百美元，而它不會讓程式更安全），請按「其他資訊 → 仍要執行」。
> 不放心的話，原始碼全部公開，你可以自己建置。

第一次啟動時 Windows 防火牆會問要不要放行。**請按「允許」** ——
按了取消的話廚房平板會連不上，而那是最難查的一種故障。
（不小心按到取消也沒關係，第 6 步有補救方法。）

---

## 2. 先看看它怎麼運作（1 分鐘）

打開之後是空的。點餐頁中間有一顆 **「載入示範菜單與桌位」** ——
按下去會建好一份菜單（4 個分類、31 個品項）與 6 張桌子。

先用它走一遍：點兩樣東西 → 結帳 → 現金 → 確認收款。
看得懂整個流程之後，再回頭建自己的菜單。

> 示範資料就是一般的商品與桌位，之後可以直接改或刪掉，不會殘留任何東西。

---

## 3. 填上自己的店名（1 分鐘）

到 **店家** 那一頁，把店名、電話、地址、統一編號填一填 —— 這些會印在收據上。

同一頁還有四個會影響金額的設定，**開店前先確認一次**：

| 設定 | 說明 |
| --- | --- |
| 營業稅率 | 台灣是 **5%**，內含在售價裡。除非你知道自己在做什麼，否則不要動它 |
| 內用服務費 | 要收一成就填 `10`，不收就留 `0`。**只對內用收**，外帶外送不收 |
| 抹零 | 夜市小吃常見「捨去到 10 元」。不確定就留「不抹零」 |
| 營業日切點 | 預設 `05:00`。做宵夜的店這一項很重要 —— 凌晨兩點的單會算前一天的業績 |
| 開桌費 | 選一個商品（例如「開桌費 $30」），開檯時自動點上「人數」份。**同一桌加點不會再收一次。** 不收就留「不收開桌費」 |

> **改費率不會回頭重算。** 已經結帳的單存的是當時算好的金額，永遠不會變
> （會自己變的報表在稅務查核上站不住）。但**還開著沒結的單會用新費率重算**，
> 所以要改的話，挑一個檯面上沒有單的時候改。

## 4. 建自己的菜單（3 分鐘）

到 **商品維護**：

1. 先建分類（飲料、主餐、小菜…）。分類是收銀畫面上方那排按鈕。
2. 每個分類底下建品項，填名稱與售價。

**先建十個最常賣的就好。** 菜單可以邊營業邊補，而一次把兩百個品項打完
的那個下午，通常會讓人放棄整件事。

不做內用的話，**桌位** 那一頁可以完全不管。

---

## 5. 接出單機（3 分鐘）

### 先把印表機接上網路

大部分機器的做法是：長按進紙鍵開機 → 它會自己印一張自我測試單 →
上面有它的 IP（像 `192.168.1.100`）。

印出來的 IP 如果是 `0.0.0.0` 或空白，代表它沒拿到網路位址：
檢查網路線、或用廠商的工具設一個固定 IP。

### 在 open-pos 裡新增它

到 **出單機 → 新增印表機**，填剛剛那個 IP，連接埠留 `9100`。

按 **測試列印**。看得懂那張紙就成功了 —— 特別是**中文有沒有正確印出來**。

| 印出來的樣子 | 意思 |
| --- | --- |
| 中文正常 | 完成，可以開店了 |
| 中文變亂碼或問號 | 到印表機設定改編碼（多數台灣機器是 Big5）。仍然不行請開 issue |
| 完全沒反應 | IP 打錯，或印表機跟電腦不在同一個網段 |

> 你的機器能用（或不能用），請回報到
> [出單機相容表](hardware-matrix.md) —— 對下一個買同一台的人是省下來的一天。

---

## 6. 廚房平板（選用，2 分鐘）

到 **系統狀態 → 區網連線**，那裡有一行大字：

```
http://192.168.x.x:8129/kds.html
```

用平板的瀏覽器打開它，就是廚房畫面。**開得起來就代表整條路都通了。**

打不開的話，那一頁上有排錯清單與防火牆指令。最常見的三個原因：

1. 平板連到的是**訪客 Wi-Fi**（訪客網路通常跟主網路隔離）
2. AP 開了「用戶端隔離 / AP Isolation」
3. 第 1 步的防火牆對話框按了取消

平板請設成 **永不休眠 + 插著電**。區網走的是 HTTP，
瀏覽器不給用 Screen Wake Lock，程式沒辦法自己讓螢幕不睡。

---

## 7. 開店前最後三件事

### ① 把主機的 IP 固定下來

到路由器把這台電腦設成 **固定 IP 或 DHCP 保留**。

不做的話，路由器哪天跳電重開，主機的 IP 會變 —— 平板連不上，
貼在桌上的 QR 全部作廢，而畫面上什麼事都沒有。
（IP 真的變了時，「區網連線」那一段會跳警告告訴你。）

### ② 設定第二個備份位置

到 **備份**，把備份位置指到那支常插著的 USB 隨身碟。

跟資料庫放在同一顆硬碟上的備份只防「誤刪」，不防「硬碟壞掉」。

### ③ 印一份復原手冊貼在收銀機旁邊

[docs/recovery.md](recovery.md) 那一頁是給店裡的人看的。
出事的當下沒有人會想去翻 GitHub。

## 每天的流程

```
開班（輸入準備金）
  → 營業（點餐 / 出單 / 結帳）
  → 關班（盲盤：先數錢再看差異）
  → 日結（產生 Z 報表，那一天就鎖起來）
```

**關班時畫面上不會顯示應有現金**，要先照面額把抽屜裡的錢數一遍。
這不是為了刁難 —— 先看到答案的人會直接照抄，而那正是
「現金差異永遠是零」的原因。不是沒有問題，是看不到問題。

---

## 出事的時候

* 主機當掉、印不出來、要還原備份 → [docs/recovery.md](recovery.md)
* 「今天中午印不出來，現在又好了」→
  **系統狀態 → 產生診斷資訊**，把那段文字貼進 issue。
  它不含品名、客人資訊或帳單明細，也不會自動上傳任何東西。

## 還沒有的東西

請在導入前讀完 [README 的「已知限制」](../README.md#已知限制請在導入前讀完)。
其中最重要的兩條：

* **紙本出單機是第一真相來源，KDS 只是輔助顯示。**
  沒有出單機的純 KDS 店家，主機故障時沒有安全的降級路徑。
* **電子發票還沒有做**（排在 v1.4）。目前印出來的是收據，不是統一發票。
