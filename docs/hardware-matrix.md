# 出單機相容表

> 這張表是社群回報累積出來的。**這個專案最有價值的資產之一。**

一個開源 POS 面對的是未知機型，而維護者手上不可能有那些機器。
你的機器能用（或不能用），對下一個買同一台的人都是省下來的一天。

**能用也請回報** —— 一張只有「壞掉的機型」的表，會讓人以為什麼都不能用。

👉 [回報你的機器](https://github.com/markku636/open-pos/issues/new?template=hardware.yml)

## 怎麼讀這張表

| 欄位 | 意思 |
| --- | --- |
| 編碼 | 中文字要用哪一種編碼送過去。選錯會印出亂碼或問號 |
| 切刀 | 送 `GS V` 之後會不會真的切紙 |
| 錢箱 | 錢箱接在印表機的腳位上，結帳時會不會彈開 |
| 狀態 | 會不會回應 `DLE EOT` —— **大多數便宜機器不會**，所以整套設計不依賴它 |

## 選機器的建議

如果你還沒買：

1. **買網路型（乙太網路孔）的。** 這是唯一不需要驅動程式的接法 ——
   廠商 SDK 常常只有 Windows DLL，Linux 根本沒有驅動。
2. **80mm 比 58mm 好用。** 一行 48 欄比 32 欄能放的東西多很多，
   長品名不會一直斷行。價差通常不大。
3. **不必追求「支援中文字庫」。** 這套系統可以走點陣圖模式，
   把字自己畫出來送過去，換任何機器印出來都一模一樣。
4. **買之前先在這張表裡找一下。** 找不到的話，買回來測完請回報。

## 印出來是亂碼怎麼辦

依序試：

1. 到「出單機」頁把**中文編碼**換一個（Big5 ↔ GB18030），按「測試列印」。
   台灣賣的機器多半吃 Big5，陸製機多半吃 GB18030。
2. 三種都試過還是亂碼 → 那台機器的內建字庫沒有中文。
   之後的版本會支援點陣圖模式（把字畫成圖送過去，不依賴機器字庫）。
3. 請把機型與症狀[回報上來](https://github.com/markku636/open-pos/issues/new?template=hardware.yml)。

## 連不上怎麼辦

1. 印表機自我測試頁上的 IP 跟你填的一樣嗎？
   （多數機型是**按住走紙鍵再開機**會印出來）
2. 收銀機跟印表機在同一個網段嗎？
3. 連接埠是 9100 嗎？（幾乎所有機器都是）
4. 用手機或另一台電腦 ping 得到那個 IP 嗎？
